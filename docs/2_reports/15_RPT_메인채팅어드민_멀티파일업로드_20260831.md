# 메인·채팅·어드민 멀티 파일 업로드 작업 완료 보고서

- 작업일: 2026-08-31
- 작업 영역: Frontend / FastAPI / Admin OCR / Admin LLM / Chat
- 대상 기능: 사진·문서 복수 선택, multipart 전송, 파일별 OCR 진행 상태
- 주요 기술: React, TypeScript, FormData, FastAPI UploadFile, OCR Job Polling
- 작업 범위: 메인·채팅 실제 복수 파일 전송, 어드민 OCR 복수 Job, 어드민 LLM 복수 파일명 조건
- 제외 범위: 채팅 원본 파일 영구 저장, 첨부 내용의 LLM Prompt 자동 주입

---

## 1. 작업 목적

작업 전 화면별 업로드 상태는 서로 달랐다.

```text
메인·채팅
→ 여러 파일 선택 가능
→ 서버에는 파일명·크기·형식 JSON만 전송
→ 실제 파일 바이트는 전송하지 않음

어드민 OCR
→ 실제 파일 업로드와 OCR 처리 가능
→ 한 번에 한 파일만 선택 가능

어드민 LLM
→ 한 개 참고 파일명만 모델 조건으로 전달
```

이번 작업은 세 화면에서 최대 5개의 사진·문서를 일관되게 선택할 수 있도록 하고,
메인·채팅은 실제 multipart 파일 전송, 어드민 OCR은 파일별 독립 분석 결과를 제공하는
것이 목적이다.

---

## 2. 최종 실행 흐름

### 2.1 메인·채팅 멀티 업로드

중심 Frontend 함수:

```text
sendMessage()
```

중심 Backend 함수:

```text
MessageService.send_message_with_uploads()
```

전체 흐름:

```text
메인 또는 채팅 MessageInput
→ 최대 5개 파일 선택·중복/형식 검사
→ FormData에 content와 files[] 구성
→ POST /api/conversations/{id}/messages/upload
→ MessageService.send_message_with_uploads()
→ 대화 소유권·게스트 한도 확인
→ validate_message_uploads()
→ 파일별 이름·형식·크기·빈 파일 검사
← 검증된 첨부 메타데이터
→ 기존 메시지 저장·응답 생성 흐름으로 복귀
← Assistant Message Response
```

텍스트 없이 파일만 메인 화면에서 전송해도 새 대화 생성 후 채팅 화면에서 업로드가
이어지도록 pending payload 판별도 수정했다.

### 2.2 어드민 OCR 멀티 분석

중심 함수:

```text
useOcrTest().analyze()
```

전체 흐름:

```text
복수 파일 선택 또는 Drag & Drop
→ 최대 5개·지원 형식·중복 검사
→ 파일별 OcrBatchItem 생성
→ 각 파일에 기존 POST /api/admin/ocr/jobs 호출
→ 파일별 Job ID Polling
← 파일별 진행률·완료 결과 또는 오류
→ 선택한 파일의 미리보기와 분석 결과 표시
→ 선택한 완료 Job을 개별 VectorDB 저장
```

기존 단일 OCR Job API와 Service는 변경하지 않고 Frontend에서 파일마다 독립 호출하므로,
기존 단일 파일 Client도 계속 사용할 수 있다.

### 2.3 어드민 LLM 참고 파일

어드민 LLM은 최대 5개의 참고 파일을 선택하고 `documentNames` 목록을 Backend로 전달한다.
현재 LLM 계약은 파일 내용을 전송하지 않고 파일명 조건만 Provider에 전달하므로 이 제한을
화면에 그대로 표시했다.

## 3. 파일 검증과 개인정보 처리

메인·채팅 허용 형식:

```text
PDF, PNG, JPG, JPEG, DOCX, PPTX, TXT, CSV
```

기본 제한:

| 항목 | 제한 |
|---|---:|
| 메시지당 파일 수 | 최대 5개 |
| 파일당 크기 | 최대 20MB |
| 파일명 | 최대 255자 |

Backend 제한은 다음 환경변수로 조정할 수 있다.

```text
MESSAGE_MAX_FILES_PER_REQUEST=5
MESSAGE_MAX_FILE_SIZE_MB=20
```

채팅 첨부는 실제 파일 바이트를 서버가 받아 검증하지만, 민감한 의료 문서를 기존 프로필용
공개 R2 URL에 저장하지 않는다. 요청 처리 후 원본은 폐기하고 DB에는 파일명·형식·크기와
`pending-upload://` 내부 참조만 저장한다. 따라서 방금 첨부한 파일은 브라우저 Blob URL로
미리볼 수 있지만 새로고침한 이전 대화에서는 원본을 다시 열 수 없다.

`dev`가 추적하는 테스트와 이번 `test_message_upload.py`를 합쳐 회귀 검증했다.

## 6. 후속 확장 시 고려사항

- 채팅 원본을 새로고침 후에도 제공하려면 의료 문서용 비공개 Object Storage와 인증된
  다운로드 또는 짧은 만료 시간의 서명 URL을 별도로 설계해야 한다.
- 첨부 내용을 LLM 답변에 사용하려면 파일별 OCR/파싱 결과를 Conversation Context 또는
  RAG 검색 흐름에 연결해야 한다.
- 현재 어드민 LLM의 참고 파일은 복수 파일명 조건만 전달하며 내용은 업로드하지 않는다.
