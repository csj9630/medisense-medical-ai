# OCR 청킹 사이즈 세분화 작업 완료 보고서

- 작업일: 2026-08-31
- 작업 영역: Admin OCR / Frontend / FastAPI / Tests
- 대상 기능: RAG Chunk Size 선택과 Backend 입력 검증
- 작업 범위: 50자 최소값, 100자 단위 옵션, Overlap 계산, API 경계 테스트
- 제외 범위: 기본값 512 변경, 실제 Chunking 알고리즘 변경

---

## 1. 작업 목적

기존 어드민 OCR의 Chunk Size 선택지는 `256`, `512`, `1024`, `2048`만 제공했고,
Backend도 100 미만 값을 거부했다. 짧은 표·문장과 세밀한 RAG 검색 실험을 지원하기 위해
100자 단위 선택지와 100자 미만 선택지를 추가했다.

---

## 2. 변경 내용

최종 선택 범위:

```text
50
100, 200, 300, ... 1900, 2000
기존 호환 옵션: 256, 512, 1024, 2048
```

- 최소 Chunk Size를 100에서 50으로 변경했다.
- 기본값은 기존과 동일한 512를 유지한다.
- 기존 256·512·1024·2048의 Overlap Preset은 변경하지 않았다.
- 새 50·100단위 값의 Overlap은 0·10·15·20%를 기준으로 5자 단위 반올림한다.
- FastAPI Form과 Pydantic Schema의 최소값을 모두 50으로 통일했다.
- 50은 정상 처리되고 49는 HTTP 422로 거부되는 테스트를 추가했다.

---

## 3. 실행 흐름

```text
Admin OCR Chunk Size 선택
→ useOcrTest가 Chunk Size와 계산된 Overlap 보관
→ multipart chunkSize/overlap 전송
→ FastAPI 최소 50·최대 4096 검증
→ OCR Workflow의 overlap < chunkSize 검증
→ 기존 create_chunks() 실행
```

Chunking 중심 함수인 `create_chunks()`의 문장 경계 탐색과 분할 알고리즘은 변경하지 않았다.
