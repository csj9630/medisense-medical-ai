# LLM AI 코어 통합 리팩터링 구현 지시서

- 작성일: 2026-08-26
- 작업 영역: AI Core / Backend / FastAPI / Tests / Dependency / Docker
- 대상 기능: Admin LLM, 일반 LLM API, Ollama, Gemini, Mock, MedGemma LoRA
- 기준 브랜치: `test/ocr-combine`
- 작업 성격: 기존 기능과 API 계약을 유지하는 구조 통합
- 선행 작업: OCR 공통 코어 통합 완료

## 1. 작업 목표

현재 분리되어 있는 다음 두 LLM 실행 계통을 하나의 `ai/llm` 코어로 통합한다.

```text
Admin LLM
→ backend/app/services/admin_llm.py
→ backend/app/services/llm/
→ Ollama / Gemini / Mock
```

```text
일반 LLM API
→ backend/app/services/llm_service.py
→ ai/llm/
→ MedGemma + LoRA Adapter
```

최종 목표:

```text
Admin API ──→ Backend Adapter ─┐
                              ├→ ai.llm Application Service
일반 LLM API → Backend Adapter ┘  → Model/Provider Registry
                                 → Ollama / Gemini / MedGemma / Mock
```

Provider 계약, Registry, Provider 구현과 실행 조율은 `ai/llm`에 둔다. FastAPI
Router, Pydantic Schema, 환경변수 해석, 인증, HTTP 오류 변환은 Backend에 남긴다.

폴더를 먼저 옮기는 것이 아니라 다음 순서를 지킨다.

```text
공통 계약 확정
→ Registry 통합
→ Provider 이관
→ MedGemma Provider 연결
→ Backend Adapter 전환
→ 기존 Import 제거
→ 중복 디렉터리 삭제
→ Dependency·Docker·테스트·문서 정리
```

- 테스트 기준선 확인

코딩 허가 없이 파일 이동, 삭제, Import 변경, Requirements 변경을 수행하지 않는다.

## 4. 작업 전 Git 및 테스트 기준선

### 4.1 Git 확인

```bash
git status --short --branch
git branch --show-current
git diff --check
```

사용자 변경이 있으면 덮어쓰지 않는다. 관련 파일에 사용자 변경이 겹치면 차이를 먼저
분석하고 임의로 되돌리지 않는다.

자동 merge, commit, push는 수행하지 않는다.

### 4.2 현재 LLM 테스트 기준선

Repository Root를 Python Path로 설정하고 Backend 테스트를 실행한다.

Windows PowerShell 예시:

```powershell
$env:PYTHONPATH = (Get-Location).Path
Set-Location backend
.\.venv\Scripts\python.exe -B -m unittest tests.test_admin_llm -v
```

현재 분석 시점 기준:

```text
Admin LLM 테스트 10개 통과
```

구현 시작 시 실제 결과를 다시 기록한다. 실패가 있으면 기존 실패인지 신규 실패인지
구분하고, 기준선 실패를 임의로 숨기거나 테스트를 삭제하지 않는다.

가능하면 전체 Backend 테스트도 기준선으로 실행한다.

```powershell
$env:PYTHONPATH = (Get-Location).Path
Set-Location backend
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
```

## 5. 반드시 유지할 외부 계약

### 5.1 Admin API

다음 Endpoint를 유지한다.

```text
GET  /api/admin/llm/models
POST /api/admin/llm/run
POST /api/admin/llm/compare
```

Frontend가 사용하는 camelCase JSON 필드를 유지한다.

주요 필드:

```text
modelId
providerModel
responseTimeSeconds
inputTokens
outputTokens
totalTokens
finishReason
isMock
availabilityMessage
```

### 5.2 일반 LLM API

다음 Endpoint를 유지한다.

```text
GET  /api/llm/models
POST /api/llm/generate
POST /api/llm/compare
```

기존 snake_case Request/Response 계약을 유지한다.

```text
model_id
model_ids
messages
content
error
```

### 5.3 모델 ID

현재 노출되는 모델 ID를 임의로 변경하거나 삭제하지 않는다.

Admin 계통:

```text
ollama-gemma3
gemini
medgemma
gemma
qwen
llama
```

MedGemma LoRA 계통:

```text
medgemma-screening
medgemma-main
```

Admin의 `medgemma`는 현재 Mock 모델이고 `medgemma-screening`, `medgemma-main`은
실제 LoRA Adapter ID다. 이름이 비슷하므로 이관 중 하나를 다른 것으로 잘못
대체하지 않는다.

### 5.4 오류 상태

기존 Domain 오류 의미와 HTTP 변환을 유지한다.

| 오류 | HTTP |
|---|---:|
| 알 수 없는 모델 | 422 또는 기존 일반 API의 404 |
| Provider 할당량 초과 | 429 |
| Provider 인증/비활성/연결 실패 | 503 |
| Provider Timeout | 504 |
| Provider Upstream 오류 | 502 |
| 안전 정책 차단 | 422 |

두 API가 현재 서로 다른 상태 코드를 반환하는 부분은 1차 이관에서 통일하지 않는다.
기존 API별 계약을 Backend Adapter에서 보존한다.

## 8. 공통 Domain 계약

### 8.1 입력 기준

Core 입력은 role/content Messages를 단일 기준으로 사용한다.

권장 형태:

```python
@dataclass(frozen=True)
class LlmMessage:
    role: Literal["system", "user", "assistant"]
    content: str


@dataclass(frozen=True)
class ProviderGenerateRequest:
    messages: tuple[LlmMessage, ...]
    document_name: str | None = None
    max_output_tokens: int | None = None
```

Admin의 단일 Prompt는 Backend Adapter에서 다음 형태로 변환한다.

```python
ProviderGenerateRequest(
    messages=(LlmMessage(role="user", content=request.prompt.strip()),),
    document_name=request.document_name,
)
```

기존 `/api/llm/generate`의 messages는 순서와 role을 유지하여 Core로 전달한다.

다음과 같이 대화 이력을 마지막 Prompt 하나로 축소하지 않는다.

```text
금지
messages[-1].content만 Provider에 전달
```

### 8.2 결과 기준

공통 결과는 가능한 다음 정보를 유지한다.

```python
@dataclass(frozen=True)
class ProviderGenerateResult:
    answer: str
    input_tokens: int | None = None
    output_tokens: int | None = None
    total_tokens: int | None = None
    finish_reason: str | None = None
```

Provider가 토큰 정보를 제공하지 않으면 추측값을 실제 토큰처럼 기록하지 않는다.
MedGemma의 토큰 수를 안전하게 계산할 수 없다면 `None`을 반환할 수 있다.

### 8.3 오류 계약

다음 Domain 예외를 `ai/llm/contracts.py` 또는 별도 `errors.py`에 둔다.

```text
UnknownLlmModelError
LlmProviderUnavailableError
LlmProviderTimeoutError
LlmProviderAuthenticationError
LlmProviderRateLimitError
LlmContentBlockedError
LlmUpstreamError
```

Domain 예외에서 FastAPI `HTTPException`을 발생시키지 않는다.

## 9. Registry 통합

### 9.1 단일 모델 정의

Admin의 `LlmModelDefinition`을 공통 모델 정의 기준으로 사용한다. MedGemma Adapter도
같은 모델 정의로 표현한다.

필수 정보:

```text
id
label
family
training_stage
description
group
provider_key
provider_model
enabled
```

MedGemma에서는 `provider_model`에 Adapter Repository 또는 Provider가 해석할 수 있는
식별자를 저장한다.

### 9.2 Registry 책임 분리

`ai/llm/registry.py`:

- 전달받은 Model Definition 저장
- 모델 목록 반환
- Model ID 조회
- Provider Key 조회
- 알 수 없는 Model/Provider Domain 예외

Backend Adapter:

- `settings.llm_ollama_model` 읽기
- `settings.llm_gemini_model` 읽기
- API Key와 Enabled 설정 읽기
- 환경별 Mock 등록 여부 결정
- Model Definition과 Provider Instance 조립

`ai/llm/registry.py`에서 `app.core.config.Settings`를 받지 않는다.

### 9.3 기존 MedGemma 공개 함수 호환

현재 다음 Import를 사용하는 코드가 깨지지 않도록 전환한다.

```python
from ai.llm import get_engine, list_models
```

단일 Registry로 바꾼 뒤에도 `list_models()`가 기존 `/api/llm/models` 응답을 만들 수
있도록 Backend Adapter 또는 얇은 호환 Projection을 제공한다. 모델 정보를 별도
상수 목록으로 다시 복제하지 않는다.

## 10. Application Service 이관

현재 `backend/app/services/llm/application.py`의 실행 순서를 보존하여
`ai/llm/application.py`로 옮긴다.

중심 함수:

```text
LlmApplicationService.run()
```

중심 흐름:

```text
Model ID 입력
→ Model Registry 조회
← Model Definition
→ Provider Registry 조회
← Provider
→ Provider.generate()
← ProviderGenerateResult
→ LlmExecutionResult 구성
← 호출자에게 반환
```

`list_models()`는 모델 목록과 Provider 가용성을 조회하지만 실제 MedGemma Base Model
또는 LoRA Adapter를 로드하지 않아야 한다.

## 12. Gemini Provider 이관

현재 다음 기능을 보존한다.

- API Key 미설정 처리
- SDK 설치 여부 확인
- 비동기 Google GenAI Client 호출
- 요청 Timeout과 동시 실행 제한
- Client 정리
- 토큰 사용량과 Finish Reason 매핑
- 안전 정책 차단 처리
- 401/403/404/429/5xx 오류 변환
- API Key 및 원문을 로그에 남기지 않는 정책

Messages를 Gemini 입력으로 변환할 때 대화 순서를 보존한다. SDK가 요구하는 role
형식과 system instruction 형식은 설치된 `google-genai` 버전의 실제 API를 확인하여
구현한다. 추측한 SDK 필드를 사용하지 않는다.

외부 Gemini로 의료 문서 또는 개인정보가 전달될 수 있으므로 다음을 지킨다.

- Prompt 원문을 INFO/ERROR 로그에 기록하지 않는다.
- API Key를 예외 메시지에 포함하지 않는다.
- Provider의 원본 오류 객체 전체를 Frontend에 전달하지 않는다.

## 14. MedGemma Provider 구현

### 14.1 목적

기존 `MedGemmaEngine`과 LoRA Adapter 기능을 공통 비동기 Provider 계약에 연결한다.
Engine을 새로 중복 구현하지 않는다.

### 14.2 Event Loop Blocking 방지

MedGemma 추론은 동기식 GPU 작업이므로 비동기 Provider에서 직접 실행하지 않는다.

```python
answer = await asyncio.to_thread(
    self._generate_locked,
    model.id,
    messages,
)
```

### 14.3 Adapter 동시성 보호

현재 Engine은 Adapter 로딩만 Lock으로 보호한다. 다음 구간 전체를 하나의 추론
경계로 보호한다.

```text
set_adapter(model_id)
→ tokenize
→ model.generate()
→ decode
```

최소 기준:

- MedGemma Provider 최대 동시 실행 기본값 1
- Adapter 선택부터 추론 완료까지 Lock 또는 동등한 보호
- Lock을 중복 취득하여 Deadlock이 생기지 않도록 Engine/Provider Lock 역할 구분

### 14.4 지연 로딩 유지

다음 동작을 유지한다.

- `import ai.llm`만으로 Torch/CUDA 모델을 로드하지 않음
- 모델 목록 조회만으로 Base Model을 로드하지 않음
- 첫 실제 MedGemma 실행 시 Base Model 로드
- Adapter도 첫 사용 시 로드
- GPU 또는 선택 패키지가 없으면 다른 Provider까지 Import 실패시키지 않음

### 14.5 Engine 오류 변환

`KeyError`, `RuntimeError`, CUDA/패키지 오류를 외부에 그대로 노출하지 않는다.
MedGemma Provider가 공통 Domain 예외로 변환한다.

## 15. Backend Adapter 전환

### 15.1 `admin_llm.py`

다음 책임을 유지한다.

- Backend Settings를 Provider 생성자 인자로 변환
- Model Definition과 Provider Registry 조립
- Admin Prompt를 Core Messages로 변환
- `LlmExecutionResult`를 Admin Pydantic Response로 변환
- Admin 비교 결과 조립
- 완료 로그에 모델 ID, Provider, 실행 시간만 기록

Provider 구현 자체와 Registry 클래스는 이 파일에 작성하지 않는다.

### 15.2 `llm_service.py`

다음 책임만 남도록 축소한다.

- 일반 API Pydantic Message를 Core Message로 변환
- 공통 Application Service 호출
- Core 결과를 기존 일반 API Response로 변환
- 기존 일반 API의 오류 상태 유지

기존 동기 Router 계약을 유지하기 위해 `asyncio.run()`을 임의로 사용하지 않는다.
공통 Core가 비동기로 전환되면 Router와 Service도 정상적인 `async/await` 흐름으로
전환한다.

### 15.3 Router

Router에서는 다음만 수행한다.

```text
HTTP 요청 수신
→ 인증 Dependency 확인
→ Backend Adapter 호출
← Response 반환
```

Provider 선택, 외부 API 호출, Prompt 조립 로직을 Router에 넣지 않는다.

## 22. 완료 기준

### 구조

- `ai/llm`이 Backend Framework에서 독립적이다.
- Provider 계약과 Application Service가 `ai/llm`에 하나만 존재한다.
- Model/Provider Registry 구현이 중복되지 않는다.
- Backend Settings는 Backend Adapter에서만 읽는다.
- Ollama, Gemini, MedGemma가 같은 Provider 계약을 구현한다.

### 기능

- Admin LLM 모델 목록과 실행·비교 기능이 유지된다.
- 일반 LLM 모델 목록과 실행·비교 기능이 유지된다.
- Admin Mock 모델 네 개가 유지된다.
- MedGemma LoRA Adapter 두 개와 대화 Messages가 유지된다.
- 한 Provider 실패가 다른 비교 결과를 불필요하게 제거하지 않는다.
- 모델 목록 조회가 GPU 모델을 로드하지 않는다.

### 성능·안전

- MedGemma 추론이 FastAPI Event Loop를 직접 Blocking하지 않는다.
- MedGemma Adapter 선택과 추론이 동시에 섞이지 않는다.
- API Key와 Prompt 원문이 로그 또는 안전하지 않은 오류 응답에 노출되지 않는다.
- CPU Backend 설치에 MedGemma GPU 패키지가 강제되지 않는다.

### 호환

- 기존 Endpoint URL이 유지된다.
- 기존 camelCase/snake_case JSON 계약이 유지된다.
- 기존 모델 ID가 유지된다.
- 기존 Admin LLM 10개 테스트와 동등 이상의 회귀 범위를 유지한다.
- OCR, Chat, Auth, Admin OCR 테스트에 회귀가 없다.
