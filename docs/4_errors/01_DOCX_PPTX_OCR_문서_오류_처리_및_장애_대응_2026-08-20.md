# DOCX/PPTX OCR 문서 오류 처리 및 장애 대응

> 상태: 이 문서는 2026-08-20 LibreOffice 기반 처리에서 발생한 장애 분석 기록이다. 이후 DOCX/PPTX 기본 처리는 직접 OOXML 추출로 전환되었다. 현재 구조는 [OCR 전체 구조 흐름](../3_flow/05_FLW_OCR_전체구조흐름_20260820.md)을 참고한다.

작성일: 2026-08-20  
대상: 관리자 OCR의 DOCX/PPTX 업로드, LibreOffice PDF 변환, Hybrid PDF/OCR 처리

## 1. 문서 목적

이 문서는 DOCX/PPTX OCR 작업 중 발생할 수 있는 오류를 분류하고, 사용자 문서 오류와 변환기 오류, 서버 자원 문제, 운영체제·저장장치 장애를 구분하여 대응하기 위한 기준을 정리한다.

특히 2026-08-20에 확인된 `09_.docx` 사례처럼 다음 조건을 가진 문서를 주요 대상으로 한다.

- OOXML ZIP과 XML 구조 검증은 통과한다.
- 매크로, 임베디드 객체, 외부 링크 등 명백한 위험 요소가 없다.
- 다른 대용량·다페이지 DOCX는 정상 처리된다.
- 특정 DOCX에서만 LibreOffice 변환 또는 후속 PDF 처리 시간이 비정상적으로 길어진다.
- 로컬 개발 PC에서는 저장장치 오류나 블루스크린까지 함께 관찰될 수 있다.

## 2. 핵심 판단 원칙

문서 하나가 LibreOffice 변환을 지연시키거나 실패하게 만들 수는 있다. 그러나 일반 사용자 프로세스의 오류가 운영체제 전체 블루스크린으로 이어지는 것은 정상적인 동작이 아니다.

따라서 다음 두 문제를 분리해서 판단해야 한다.

1. 문서별 재현 트리거
   - 특정 레이아웃, 오래된 저장 정보, 글꼴 호환성 또는 변환기 호환 문제
   - LibreOffice 변환 지연, 비정상 PDF 생성 또는 후속 PDF 분석 지연을 유발할 수 있음
2. 시스템 안정성 문제
   - SSD, SATA 케이블·포트, 스토리지 드라이버, 페이지 파일, RAM 등
   - 애플리케이션 부하를 처리하지 못하고 운영체제 장애로 확대될 수 있음

특정 문서가 재현 조건이라는 사실과 PC 또는 서버에 시스템 문제가 있다는 사실은 동시에 성립할 수 있다.

## 3. 현재 OCR 처리 흐름

```text
DOCX/PPTX 업로드
  -> 확장자·MIME·파일 크기 검증
  -> OOXML ZIP/필수 엔트리/CRC/압축 해제 크기 검증
  -> 작업별 임시 디렉터리 생성
  -> 격리된 LibreOffice 프로필로 PDF 변환
  -> 변환 PDF 크기·시그니처·페이지 수 검증
  -> 기존 Hybrid PDF 분석
     -> Native Text 사용
     -> 이미지 포함 페이지 Hybrid OCR
     -> 텍스트 부족 페이지 전체 OCR
  -> 텍스트 정제 및 Chunking
  -> 결과 반환 또는 Job failed 처리
```

현재 기본 설정은 다음과 같다.

| 항목 | 기본값 | 목적 |
| --- | ---: | --- |
| Office 변환 제한 시간 | 120초 | 무한 변환 방지 |
| 변환 PDF 최대 크기 | 50MB | 비정상 출력 제한 |
| PDF 렌더링 해상도 | 200 DPI | 스캔 페이지 OCR |
| Native Text 최소 문자 수 | 20자 | 페이지 OCR 여부 결정 |
| Office 압축 해제 최대 크기 | 200MB | ZIP 폭탄 방지 |
| Office ZIP 엔트리 최대 개수 | 5,000개 | 비정상 OOXML 방지 |

## 4. 오류 분류

### 4.1 입력 검증 오류

다음 오류는 LibreOffice 실행 전에 차단한다.

- 허용하지 않은 확장자 또는 MIME
- DOCX/PPTX 확장자와 실제 내부 형식 불일치
- 필수 OOXML 엔트리 누락
- 손상된 ZIP 또는 CRC 오류
- 암호화된 문서
- 경로 순회 형태의 ZIP 엔트리
- 압축 해제 크기 또는 엔트리 개수 초과

처리 결과:

- `DocumentValidationError`
- OCR Job은 `failed`
- 사용자에게 파일 손상 또는 지원하지 않는 형식임을 안내

### 4.2 Office 변환 오류

다음 오류는 DOCX/PPTX를 PDF로 변환하는 단계에서 발생한다.

- LibreOffice 미설치 또는 실행 파일 경로 오류
- LibreOffice 비정상 종료
- 제한 시간 안에 변환되지 않음
- PDF가 생성되지 않음
- 빈 PDF가 생성됨
- 변환 PDF 최대 크기 초과

처리 결과:

- `OfficeConversionError`
- OCR Job은 `failed`
- 원본 문서를 Word/PowerPoint에서 다시 저장하거나 PDF로 변환하도록 안내

### 4.3 변환기 병적 입력 오류

정적 OOXML 검증에는 정상이지만 특정 문서의 레이아웃 계산에서 변환기가 지나치게 오래 실행되는 경우다.

가능한 원인:

- 오래되거나 서로 맞지 않는 페이지 계산 메타데이터
- Word와 LibreOffice 간 레이아웃 호환 문제
- 특정 글꼴 대체 및 줄바꿈 재계산
- 문서 저장 프로그램이 남긴 비표준 또는 불필요한 OOXML 상태
- LibreOffice 특정 버전의 문서별 변환 결함

이 오류는 파일 크기, 페이지 수, 표·이미지 개수만으로 사전에 완전히 판별할 수 없다.

### 4.4 변환 PDF 검증 오류

LibreOffice가 파일을 생성했더라도 다음 검증에 실패하면 후속 OCR로 전달하지 않는다.

- PDF 시그니처 오류
- 암호화된 PDF
- 페이지가 없는 PDF
- 허용 페이지 수 초과
- PyMuPDF에서 열 수 없는 PDF

### 4.5 PDF 분석 및 OCR 오류

- Native Text 추출 실패
- 변환 결과에서 일부 페이지의 텍스트가 비정상적으로 누락됨
- 페이지 전체가 OCR 대상으로 잘못 분류됨
- 고해상도 렌더링 중 메모리 사용량 증가
- PaddleOCR 모델 로딩 실패
- 이미지 전처리 최대 크기·픽셀 제한 초과

Native Text가 충분한 DOCX는 정상적으로 변환되면 PaddleOCR를 실행하지 않는 것이 일반적이다. 따라서 DOCX 작업 지연이 항상 OCR 엔진 부하를 의미하지는 않는다.

### 4.6 시스템 장애

다음 현상은 일반적인 문서 오류 범위를 벗어난다.

- Windows 블루스크린
- 시스템 전체 멈춤 또는 강제 재부팅
- Disk 이벤트 51과 같은 페이지 파일·저장장치 I/O 오류
- `volmgr` 덤프 기록 실패
- C: 볼륨 또는 섀도 복사본 I/O 오류
- 컨테이너·서버 노드 전체가 응답하지 않음

이 경우 문서 오류 메시지만 개선해서는 해결할 수 없다. 저장장치, 메모리, 드라이버, 전원 및 호스트 상태를 별도로 점검해야 한다.

## 5. `09_.docx` 사례 분석

### 5.1 재현 결과

- Google Drive의 원본으로 작업했을 때 Windows 블루스크린이 두 차례 발생했다.
- 로컬 폴더로 복사한 문서에서도 PC 상태가 악화되어 사용자가 서버 포트를 수동 종료했다.
- 다른 1페이지 DOCX는 정상 처리됐다.
- 표와 이미지가 포함된 11페이지 이력서 DOCX도 정상 처리됐다.

따라서 Google Drive 가상 드라이브와 DOCX 페이지 수는 주원인으로 보기 어렵다.

### 5.2 정적 구조 검사

`09_.docx` 검사 결과:

| 항목 | 결과 |
| --- | --- |
| 파일 크기 | 24,196바이트 |
| OOXML 엔트리 | 13개 |
| 압축 해제 전체 크기 | 약 133KB |
| 문단 | 218개 |
| 추정 페이지 | 약 8페이지 |
| 표·이미지·도형 | 없음 |
| 매크로·임베디드 객체 | 없음 |
| 외부 관계 | 없음 |
| ZIP/CRC/XML | 정상 |

명백한 손상 문서나 압축 폭탄은 아니다.

다만 문서 속성에는 `1페이지·13문단`으로 기록되어 있으나 실제 XML에는 `218문단`과 7개의 렌더링 페이지 구분이 있다. 이는 문서 속성 또는 페이지 계산 정보가 실제 내용과 맞지 않는 상태임을 보여준다.

이 불일치는 파일 손상을 확정하는 증거는 아니지만 LibreOffice가 문서를 열 때 전체 레이아웃을 다시 계산하게 만드는 요인이 될 수 있다.

### 5.3 시스템 이벤트와의 관계

개발 PC에서는 문서 테스트와 별도로 다음 문제가 확인됐다.

- `0x00000154 UNEXPECTED_STORE_EXCEPTION` 3회
- 테스트 이전 날짜에도 동일 중지 코드 발생
- 시스템 SSD `Harddisk0`에서 최근 14일간 Disk 이벤트 51이 161회 발생
- C: 볼륨 섀도 복사본 I/O 오류
- 블루스크린 당시 크래시 덤프 작성 오류

결론:

- `09_.docx`는 비정상 작업을 재현시키는 문서별 트리거일 가능성이 높다.
- 블루스크린은 문서 오류만으로 설명할 수 없으며 개발 PC의 스토리지 계층 문제도 함께 존재한다.
- 파일 문제와 PC 문제 중 하나만 선택하는 방식으로 판단하면 안 된다.

## 6. 운영 대응 절차

### 6.1 즉시 중단 조건

다음 중 하나가 발생하면 동일 문서의 자동 재시도를 중단한다.

- Office 변환 timeout
- 동일 파일 해시에서 2회 이상 변환 실패
- 시스템 메모리 또는 디스크 사용량이 임계치에 접근
- LibreOffice 프로세스가 제한 시간 이후에도 남아 있음
- 호스트 I/O 오류 또는 시스템 장애 징후

### 6.2 사용자 안내

문서 변환 오류 시 권장 안내:

```text
문서의 내부 구조는 확인되었지만 PDF 변환을 완료하지 못했습니다.
Microsoft Word 또는 PowerPoint에서 새 파일로 다시 저장하거나 PDF로 내보낸 뒤 다시 시도해 주세요.
```

변환 timeout 시 권장 안내:

```text
문서 변환 시간이 제한을 초과했습니다.
동일 파일의 반복 실행은 중단되었으며, 문서를 새 DOCX/PPTX 또는 PDF로 저장한 뒤 다시 시도해 주세요.
```

### 6.3 문서 정규화 방법

원본을 직접 변경하지 않고 복사본에서 다음 순서로 진행한다.

1. Microsoft Word의 `열기 및 복구`로 연다.
2. 새 빈 DOCX에 내용을 복사한다.
3. 기존 문서의 마지막 문단 기호는 복사하지 않는다.
4. 새 파일명으로 저장한다.
5. Word에서 PDF 내보내기가 정상인지 먼저 확인한다.
6. 정상 PDF를 OCR에 입력한다.

### 6.4 안전한 재현 순서

시스템 상태가 안정적이고 중요 파일 백업이 완료된 환경에서만 다음을 수행한다.

1. 문서의 SHA-256 기록
2. DOCX/PPTX 정적 검증만 실행
3. OCR 서버와 분리된 프로세스에서 Office→PDF 변환만 실행
4. 생성된 PDF 크기와 페이지 수 확인
5. 변환 PDF를 대상으로 Hybrid PDF 처리만 실행
6. 각 단계의 시간, CPU, 메모리, 임시 파일 크기 기록

블루스크린이나 Disk I/O 오류가 발생한 호스트에서는 동일 문서를 반복 실행하지 않는다.

## 8. 권장 오류 처리 구조

```text
업로드
  -> SHA-256 계산
  -> 정적 검증
     -> 실패: validation_error
  -> 최근 동일 해시 실패 확인
     -> 반복 실패: retry_blocked
  -> 격리 변환 작업 실행
     -> 정상 종료: PDF 검증으로 이동
     -> timeout: 전체 프로세스 트리 종료 및 conversion_timeout
     -> 비정상 종료: conversion_failed
  -> 변환 PDF 검증
     -> 실패: converted_pdf_invalid
  -> PDF 구조 분석
     -> 페이지별 Native/Hybrid/OCR 경로 기록
  -> 결과 반환
```

로그에는 문서 본문이나 개인정보를 남기지 않고 다음 정보만 기록한다.

- 파일 해시의 일부 또는 내부 Job ID
- 원본 확장자
- 원본·압축 해제·변환 PDF 크기
- OOXML 엔트리 수
- 변환기 버전
- 단계별 시작·종료 시각과 소요 시간
- 변환 종료 코드
- timeout 여부
- PDF 페이지 수
- Native/Hybrid/OCR 대상 페이지 수
- 프로세스 종료 및 잔존 여부

## 9. 구현 우선순위 제안

### P0: 장애 확산 방지

- Office 변환 timeout 후 LibreOffice 프로세스 트리 종료 확인
- 동일 파일 해시의 즉시 자동 재시도 금지
- 문서 변환과 OCR 단계별 시간 로깅
- 운영 환경의 메모리·CPU·작업 시간 제한 설정

### P1: 원인 추적성

- 진행 상태에 `validation`, `converting`, `pdf_analyzing`, `ocr` 단계 명확화
- 변환 PDF 크기·페이지 수·OCR 대상 수 로깅
- 오류 코드를 사용자 메시지와 내부 진단 코드로 분리
- 문제 문서 재현용 안전한 격리 테스트 절차 마련

### P2: 사용자 복구 지원

- Word/PowerPoint 재저장 또는 PDF 업로드 안내
- 변환 실패 문서에 대한 자동 재시도 대신 수동 재처리 제공
- 문서 정규화 가이드 UI 연결

## 10. 테스트 항목

### 10.1 정상 문서

- 1페이지 텍스트 DOCX
- 10페이지 이상 텍스트 DOCX
- 다수의 표와 이미지가 있는 DOCX
- 1슬라이드 PPTX
- 다슬라이드 PPTX

### 10.2 비정상 입력

- 손상된 ZIP
- 필수 엔트리 누락
- 암호화된 OOXML
- 확장자와 내부 형식 불일치
- 압축 해제 크기 초과
- 엔트리 개수 초과
- 변환 PDF 페이지 수 초과

### 10.3 병적 변환

- LibreOffice가 제한 시간을 초과하는 문서
- timeout 후 자식 프로세스가 남는 상황
- PDF는 생성되지만 열 수 없는 상황
- Native Text가 모두 누락되어 전체 페이지가 OCR로 전환되는 상황
- 동일 파일을 반복 요청하는 상황

## 11. 운영 체크리스트

- [ ] 중요 데이터가 백업된 호스트에서 테스트하는가
- [ ] 문제가 발생한 동일 문서를 자동 재실행하지 않는가
- [ ] 진행 상태가 어느 단계에서 멈췄는지 기록했는가
- [ ] LibreOffice 프로세스가 남아 있지 않은가
- [ ] CPU, 메모리, C: 여유 공간을 확인했는가
- [ ] Windows 또는 서버의 저장장치 I/O 오류를 확인했는가
- [ ] 문서를 Word/PowerPoint에서 새 파일 또는 PDF로 정규화했는가
- [ ] 원본 문서의 내용이 로그에 노출되지 않았는가

## 12. 현재 조치 상태

이 문서는 분석 및 운영 대응 기준만 추가한 것이다.

- OCR 코드 변경 없음
- 오류 처리 로직 변경 없음
- 문제 DOCX 재실행 없음
- 프로세스 종료 방식 변경 없음

실제 코드 보완은 별도 구현 작업과 테스트를 통해 진행해야 한다.
